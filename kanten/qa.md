# ISO/IEC 25010:2023 ソフトウェア品質特性(観点細分化版)

ISO/IEC 25010:2023 の製品品質モデルは、9個の品質特性と40個の品質副特性で構成される。

| No. | 品質特性                                       | 品質副特性                                                                                                                                                                                                                                                   |
| --: | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|   1 | 機能適合性<br>Functional suitability            | 機能完全性（Functional completeness）<br>機能正確性（Functional correctness）<br>機能適切性（Functional appropriateness）                                                                                                                                                    |
|   2 | 性能効率性<br>Performance efficiency            | 時間効率性（Time behaviour）<br>資源効率性（Resource utilization）<br>容量満足性（Capacity）                                                                                                                                                                                 |
|   3 | 互換性<br>Compatibility                       | 共存性（Co-existence）<br>相互運用性（Interoperability）                                                                                                                                                                                                            |
|   4 | インタラクション容易性（対話性）<br>Interaction capability | 適切度認識性（Appropriateness recognizability）<br>習得性（Learnability）<br>運用操作性（Operability）<br>ユーザエラー防止性（User error protection）<br>ユーザエンゲージメント（利用者関与性）（User engagement）<br>インクルーシビティ（包摂性）（Inclusivity）<br>ユーザ支援性（User assistance）<br>自己記述性（Self-descriptiveness） |
|   5 | 信頼性<br>Reliability                         | 無障害性（Faultlessness）<br>可用性（アベイラビリティ）（Availability）<br>障害許容性（耐故障性）（Fault tolerance）<br>回復性（Recoverability）                                                                                                                                               |
|   6 | セキュリティ<br>Security                         | 機密性（Confidentiality）<br>インテグリティ（Integrity）<br>否認防止性（Non-repudiation）<br>責任追跡性（Accountability）<br>真正性（Authenticity）<br>耐攻撃性（Resistance）                                                                                                                  |
|   7 | 保守性<br>Maintainability                     | モジュール性（Modularity）<br>再利用性（Reusability）<br>解析性（Analysability）<br>修正性（Modifiability）<br>テスト可能性（試験性）（Testability）                                                                                                                                         |
|   8 | 柔軟性<br>Flexibility                         | 適応性（Adaptability）<br>拡張性（Scalability）<br>インストール性（設置性）（Installability）<br>置換性（Replaceability）                                                                                                                                                            |
|   9 | 安全性<br>Safety                              | 運用制約性（Operational constraint）<br>リスク識別性（Risk identification）<br>フェールセーフ（Fail safe）<br>危険警告性（Hazard warning）<br>統合時安全性（Safe integration）                                                                                                                 |

## 詳細
各観点の下に、より具体的なチェック項目・確認例をぶら下げている。

### 機能適合性(Functional Suitability)

#### 機能完全性(Functional Completeness)

- 要件・仕様の網羅性(要求された機能がすべて実装されているか)
  - 要件定義書・仕様書の項目と実装機能の突合表の有無
  - 「今回対象外」とした要件の合意記録と管理
  - 非機能要件に紐づく機能(監視用エンドポイント、ログ画面等)の実装漏れ確認
- 暗黙の要件(業界慣習・法令・商習慣)の考慮
  - 業界特有の帳票・手続き(締め、月次報告等)の要否確認
  - 適用法令(個人情報保護法、業法等)由来の機能要件の洗い出し
  - 「言われていないが当然あるべき」機能(印刷、CSV出力等)の確認
- ユースケース・ユーザーストーリーの網羅
  - 全アクター(顧客、管理者、運用者等)ごとのユースケース列挙
  - 主フローだけでなく代替フロー・例外フローのシナリオ化
  - ユースケースとテストケースの対応付け
- CRUD の網羅(作成・参照・更新・削除の抜け漏れ)
  - エンティティ×操作の CRUD マトリクスの作成
  - 作成(単発/一括/複製)・更新(単項目/一括)のバリエーションの要否
  - 「作れるが消せない」「登録後に修正できない」データの有無確認
- データライフサイクル全体の機能網羅(取得→利用→保管→アーカイブ→削除)
  - 各段階に対応する機能(取込、閲覧、アーカイブ、削除)の対応表
  - 保持期間満了時の自動処理(削除・匿名化)の有無
  - アーカイブ後データの参照・復元手段の提供
- 論理削除・物理削除の使い分けと復元手段
  - データ種別ごとの削除方式(論理/物理)の方針定義
  - 論理削除データの検索・集計への影響(混入・除外)の仕様化
  - 誤削除時の復元操作の提供と実行権限の定義
- 変更履歴・世代管理機能の要否と網羅
  - 履歴が必要なエンティティの特定(監査・トレース要件からの導出)
  - 変更前後の値・変更者・日時の記録粒度の定義
  - 過去版の閲覧・比較・復元の可否
- 取消・訂正・差戻し・返品など逆方向操作の提供
  - 各業務トランザクションに対する取消・赤伝処理の有無
  - 確定後データの訂正手順(訂正伝票方式か直接修正か)の定義
  - ワークフローの差戻し・引き戻し操作の提供
- 下書き・一時保存・承認前状態の扱い
  - 長い入力フォームでの一時保存の要否
  - 下書きデータの可視範囲(本人のみか共有か)の定義
  - 承認前データの集計・検索への含め方の仕様化
- 一括処理系機能(一括登録・一括更新・インポート)の網羅
  - 大量データ登録・更新のインポート手段(CSV 等)の有無
  - 一部エラー時の挙動(全件ロールバックか部分成功か)の仕様化
  - 取込結果(成功/失敗件数、エラー明細)のレポート提供
- 検索手段の網羅(部分一致、複合条件、全文検索、横断検索)
  - 利用者の探し方(ID 直指定、曖昧検索、絞り込み)ごとの手段提供
  - 検索対象範囲の網羅(備考欄・添付ファイル内も対象か)
  - 検索条件の保存・再利用と結果の並び替え
- 正常系ケースの網羅性
  - 主要業務シナリオの端から端まで(E2E)の動作確認
  - 入力パターン(任意項目の有無、選択肢の組合せ)の網羅
  - データ件数の違い(0件、1件、多数件)での正常動作
- 異常系・例外ケースの網羅性
  - 入力エラー、通信断、外部サービスエラー時の挙動定義
  - 業務例外(在庫不足、与信 NG 等)ごとの処理の仕様化
  - 異常時のメッセージとリカバリ手段の提供
  - タイムアウト・二重操作・中断からの復帰など操作起因の異常の網羅
- 境界条件・限界値の考慮
  - 最大文字数・最大件数・上限金額のちょうど/超過時の挙動
  - 0・マイナス・空・最小値の扱いの定義
  - 日付境界(月初月末、年度替わり、期限当日)の扱い
- 機能間の組み合わせの網羅(機能A×機能Bの同時利用)
  - 排他が必要な機能の組合せ(締め処理中の入力等)の洗い出し
  - 機能を跨ぐデータの受け渡し(検索→一括更新等)の整合
  - 同時に有効化できる設定同士の矛盾チェック
- 権限・ロールごとの提供機能の網羅
  - ロール×機能の権限マトリクスの整備
  - 各ロールで業務が完結すること(必要機能の欠落がないこと)の確認
  - 代理・兼務・権限委譲時の機能利用可否の定義
- チャネル間(Web/モバイル/API)の機能同等性
  - チャネルごとの提供機能一覧と意図的な差分の明確化
  - モバイル非対応機能の代替手段の案内
  - API のみ/画面のみでしか行えない操作の把握
- 新旧システム・競合製品との機能同等性(フィーチャーパリティ)
  - 旧システム機能の棚卸しと対応方針(移行/廃止)の決定
  - 廃止機能の利用者への影響評価と代替案内
  - 競合比較での必須機能(テーブルステークス)の充足確認
- 帳票・通知・メール・エクスポート等の出力系機能の網羅
  - 必要な帳票・通知の一覧化と発生契機の定義
  - 出力形式(PDF/CSV/Excel)ごとの要否
  - 通知の宛先・条件・文面の網羅と設定変更可能性
- 管理・運用機能(マスタ保守、設定、ログ閲覧)の網羅
  - 全マスタに対する保守手段(画面または運用手順)の提供
  - 運用者向け機能(再送、締め解除、代行操作)の整備
  - リリースなしで変更できる設定範囲の定義
- 移行データ・過去データへの機能適用可否
  - 移行データに対する検索・修正・帳票出力の動作確認
  - 旧仕様データ(項目欠損、旧コード体系)の表示・編集の扱い
  - 過去日付データへの現行ルール適用の是非の判断
- 要件トレーサビリティ(要件⇔実装⇔テストの対応の完全性)
  - 要件 ID と設計・実装・テストケースの対応表の維持
  - 変更要求発生時の影響範囲の追跡可否
  - どの要件にも紐づかない実装(仕様外機能)の検出
- ワークフロー・承認経路のパターン網羅(直列/並列/条件分岐)
  - 金額・種別による承認段数の変化のパターン化
  - 代理承認・不在時の委任・引き上げ承認の提供
  - 承認途中の取り下げ・条件変更時の再承認の扱い
- 外部公開インターフェース(API・ファイル連携)の機能網羅
  - 画面でできる操作のうち API でも提供する範囲の定義
  - 外部からのデータ取得・投入手段の網羅
  - API の機能不足が手作業運用を生んでいないかの確認
- システム停止時の業務継続手段(代替運用)の提供
  - 停止中の代替手段(紙様式、オフライン処理)の定義
  - 復旧後の後追い入力・データ取り込みの手段
  - 代替運用の発動判断と手順の明文化
  
#### 機能正確性(Functional Correctness)

- 計算結果の正確さ(丸め誤差、桁あふれ、精度)
  - 計算仕様(数式・精度・丸め位置)の文書化と実装の一致
  - 極端に大きい/小さい値でのオーバーフロー・アンダーフロー確認
  - 手計算・別実装との突合による検算
  - 繰り返し計算・大量集計での累積誤差の評価
- 浮動小数点誤差への対処(金額は固定小数点・整数演算)
  - 金額・数量計算での decimal/整数型の使用(float の禁止)
  - 2 進小数誤差(0.1+0.2 問題)の混入箇所の点検
  - 言語・DB・帳票間の型変換による精度落ちの確認
- 丸め・切り捨て・切り上げ規則の一貫性
  - 丸め方式(四捨五入/銀行丸め/切捨て)の全画面・全帳票での統一
  - 丸めのタイミング(明細ごとか合計時か)の定義
  - 法令・契約で丸め方が定まる計算(消費税等)の準拠確認
- 通貨・税・利率など業務ルールへの適合
  - 税率・利率の改定に備えた適用開始日付き管理
  - 端数処理・非課税・軽減税率など特例の実装確認
  - 業務部門による計算結果の検収(サンプル突合)
- 集計の二重計上・計上漏れの防止(明細と合計の一致)
  - 明細合計と集計値の突合チェック(バッチ・画面)
  - 集計対象条件(ステータス、期間)の定義の明確さ
  - 訂正・取消データの集計への反映(赤黒処理)の正しさ
- 検索・集計・ソート・フィルタ結果の正確さ
  - 検索条件と結果の対応(ヒットすべきものが漏れないこと)
  - フィルタ組合せ時の AND/OR 解釈の仕様どおりの動作
  - 集計軸を切り替えても総合計が一致することの確認
- ソート順・照合順序(大文字小文字、五十音、Unicode)の正しさ
  - DB の照合順序(collation)とアプリ側ソートの一致
  - 日本語(濁点・拗音・長音)の並び順の期待との一致
  - NULL・空値・記号のソート位置の定義
- ページング境界でのデータ重複・欠落(取得中の更新の影響)
  - オフセット方式でのページ送り中の重複・欠落の検証
  - カーソル/キーセット方式のページネーションの採用検討
  - ソートキーの一意性確保(同値時のタイブレーク)
- 出力データの正確さ(表示、帳票、エクスポート)
  - 画面表示と帳票・CSV 出力の値の一致
  - 桁区切り・通貨記号・日付書式の指定どおりの整形
  - 長い文字列・特殊文字の欠け・文字化けの確認
- データ整合性(入力と保存内容の一致)
  - 入力値の暗黙変換(トリム、全半角変換)の仕様化
  - 保存→再表示での値の往復一致(ラウンドトリップ)
  - 関連テーブル間の参照整合性(外部キー)の維持
- 並行実行時の整合性(排他制御、競合状態、デッドロック)
  - 楽観/悲観ロックの使い分けと更新競合時の挙動定義
  - 同一データの同時更新テストの実施
  - デッドロック発生時の検知・リトライ処理
- 在庫引当・残高更新など競合の多い業務処理の正確さ
  - 引当・残高計算の直列化(ロック・キュー)の設計
  - マイナス在庫・残高不整合の検知と補正手段
  - 高並行負荷をかけた整合性テストの実施
- 冪等性(同一操作の再実行で結果が変わらないこと)
  - リトライ・再送で二重登録されないキー設計(冪等キー)
  - バッチ再実行時の重複処理防止
  - 決済・メール送信など副作用のある処理の再実行安全性
- NULL・空文字・ゼロ・未設定の区別と取り扱い
  - 「未入力」と「0」「空文字」の意味の区別の仕様化
  - NULL を含む計算・比較・集計結果の定義
  - 画面上の未設定の表現(空欄/「-」/「未設定」)の統一
- ID・採番の一意性と欠番・重複時の扱い
  - 採番方式(連番/UUID)の選定と重複防止の仕組み
  - 取消時の欠番許容ポリシーの明確化
  - 分散環境・高負荷時の採番衝突の検証
- キャッシュと実データの整合(更新反映のタイミング)
  - キャッシュ無効化方式(更新時パージ/TTL)の設計
  - 古いキャッシュ表示が業務に与える影響の評価
  - 複数サーバー間のキャッシュ不整合の考慮
- マスタ・レート類の適用時点(取引時点か処理時点か)の正確さ
  - 為替・税率・単価の適用日ルールの仕様化
  - マスタ改定後の過去取引の再計算要否の定義
  - 予約処理・遡及処理での適用時点の検証
- 状態遷移の正しさ(許可されない遷移の拒否)
  - 状態遷移図と実装の一致(遷移可否マトリクス)
  - 画面を経由しない操作(API 直接呼び出し)での不正遷移の拒否
  - 並行操作による不整合遷移(承認済みデータの編集等)の防止
- 通知・メールの宛先・内容・送信タイミングの正確さ
  - 宛先抽出条件(対象者の選定、配信停止者の除外)の正しさ
  - 差し込み項目(宛名・金額)の取り違え防止
  - 再実行時の二重送信・送信漏れの確認
- 締め処理・集計時点(カットオフ)の扱いの正確さ
  - 締めの基準時刻・タイムゾーンの定義
  - 締め後に到着した遡及データの扱い(翌期計上等)の定義
  - 締め処理実行中の新規登録の制御
- 日付・時刻・タイムゾーン・うるう年処理の正確さ
  - 保存は UTC・表示はローカル等の方針統一
  - うるう年 2/29 を含む日付計算・年齢計算の確認
  - サーバー・DB・クライアント間のタイムゾーン差の影響確認
- 月末日・月跨ぎ計算の定義(1/31 の 1 か月後など)
  - 「1 か月後」「月末」の定義(2/28 か 3/3 か)の仕様化
  - 締め日・支払サイトの計算規則の確認
  - 月次バッチの実行日と対象期間のずれの確認
- 夏時間(DST)切替日時の処理
  - 存在しない時刻・二重に存在する時刻の扱いの定義
  - 切替日を跨ぐ期間計算・スケジュール実行の確認
  - 海外拠点・海外ユーザーがいる場合の影響範囲の把握
- 和暦・改元・年度切替への対応
  - 改元時に元号マスタ等で追従できる仕組み
  - 元年表記・改元日を跨ぐ帳票の表示確認
  - 会計年度・学年度など複数の年度定義の使い分け
- 週の開始曜日・週番号の定義の一貫性
  - 週の開始(日曜/月曜)の全画面・全集計での統一
  - 週番号の定義(ISO 週番号か独自か)の明確化
  - 年初・年末の週の帰属(第 1 週の定義)の確認
- 文字列処理の正確さ(全角半角、サロゲートペア、絵文字)
  - 文字数カウント基準(バイト/コードポイント/書記素)の統一
  - サロゲートペア・絵文字・結合文字の切り出し/切り詰めの安全性
  - 全半角変換・Unicode 正規化(NFC/NFKC)の適用方針
- 多通貨・多言語データ混在時の計算・表示の正確さ
  - 通貨ごとの小数桁数(JPY=0 桁等)の正しい処理
  - 換算レートの適用時点と換算差額の扱い
  - 通貨記号・桁区切りのロケール別表示
- 乱数・抽選・配分処理の公平性
  - 抽選・割り当てロジックの偏りの検証
  - 乱数の予測可能性・再現性(シードの扱い)の設計
  - 結果の検証可能性(抽選ログ・監査対応)
- AI・機械学習を用いた機能の出力の妥当性
  - 精度指標(適合率・再現率等)の定義と継続計測

### 性能効率性(Performance Efficiency)

  - ばらつき要因(GC、バッチ同時実行、キャッシュミス)の特定
  - 「たまに遅い」という報告を再現・調査できる手段の確保
- スループット(単位時間あたり処理件数)

- レイテンシ(遅延)

- 初回表示・体感速度(Web なら LCP・TTI 等)
  - Core Web Vitals(LCP、INP、CLS)の計測と目標設定
  - スケルトン表示・段階的レンダリングによる体感改善
  - 実ユーザー計測(RUM)と合成計測の併用
- 起動・終了時間
  - アプリ・サービスの起動所要時間の計測
  - 起動時初期化処理の遅延実行化(必要になるまで待つ)
  - デプロイ・再起動直後のウォームアップの要否
- コールドスタート時間(サーバーレス・JIT 環境)
  - コールドスタートの発生頻度と所要時間の計測
  - 事前確保(プロビジョンドコンカレンシー等)・ウォームアップの検討

- 非同期処理・画面描画の待ち時間
  - 非同期化すべき重い処理の特定基準(数秒超等)の設定
  - 処理中表示と完了通知の提供
  - 完了確認の方式(ポーリング間隔/プッシュ通知)の設計

  - タイムアウト時のユーザー向け挙動(エラー表示/リトライ)の定義

  - 長時間トランザクションの検出と分割
  - 同一行への更新集中(ホットスポット)を避ける設計

  - 処理時間が件数に比例/二乗で増える処理の特定
  - 性能トレンドの継続監視(徐々に進む劣化の検知)

  - スケジュール変更時の関係者調整プロセス

#### ユーザーエラー防止性(User Error Protection)

  - エラー箇所の特定しやすさ(項目単位のエラー表示)

- 制約による誤り防止(自由入力より選択式にする等)
  - 選択式・日付ピッカー等による入力形式の制約
  - 入力可能範囲の制限(過去日不可等)の実装
  - 制約が厳しすぎて正しい値を弾いていないことの確認
- 全角/半角・前後空白の自動補正(貼り付けデータのクレンジング)
  - トリム・全半角統一の自動適用
  - 補正した事実の扱い(黙って直すか通知するか)の方針統一
  - ハイフン・長音などの記号ゆれの吸収
- 重複登録・類似データの検知と警告
  - 登録時の重複チェック(キー項目、名寄せ)
  - 類似データ検出時の警告と確認フロー
  - 重複と判定する基準の明確化
- 類似データ・類似項目の混同防止(似た名称の表示上の区別)
  - 似た名称の並び表示時の識別情報(コード等)の併記
  - 選択肢の識別しやすい表示順・グルーピング
  - テスト用・本番用データの見た目の区別
- 操作対象の明確化(どのレコードに作用するかの表示)
  - 確認ダイアログへの対象名・件数の明示
  - 一括操作時の対象一覧の事前表示
  - 選択中レコードの視覚的な強調
- 単位・桁の取り違え防止(千円/円、% など)
  - 単位の入力欄への常時表示
  - 桁区切り表示による桁誤りの気づきやすさ
  - 異常な桁の値への警告(前回値との大幅乖離等)
- 破壊的操作(削除等)前の確認・保護
  - 確認ダイアログ・対象名の再入力等による保護
  - 削除の取り消し猶予(ゴミ箱、Undo 期間)の提供
  - 大量データへの破壊的操作の追加保護
- 危険な操作の分離(ボタン配置・二段階操作)
  - 危険ボタンと通常ボタンの距離・色の区別
  - 二段階操作(メニュー展開後に実行等)の採用
  - デフォルトフォーカスを安全側の選択肢に置くこと
- 権限外操作の非表示/無効化の適切な使い分け
  - 非表示にするか無効化して見せるかの方針統一
  - 無効化時の理由表示(なぜ押せないか)
  - 画面制御に頼らずサーバー側でも権限チェックすること
- 期限切れ・締め後操作の防止
  - 締め済み期間・確定済みデータの編集ロック

  - 例外的に解除する場合の権限と記録
- 二重送信・二度押しへの対策(冪等性)
  - 送信ボタンの二度押し防止(処理中の無効化)
  - サーバー側の重複リクエスト排除(トークン・冪等キー)
  - リロード・戻る操作による再送信の防止(PRG パターン)
- 自動保存・下書きによる作業消失の防止
  - 定期的な自動保存とその状態の明示
  - クラッシュ・切断後の復元
  - 自動保存と手動保存の関係(どちらが正か)の明確化
- エラーメッセージの分かりやすさと対処方法の提示
  - 原因と次にすべきことが分かる文面
  - 技術用語・コードだけのメッセージの排除
  - 問い合わせ時に使える情報(エラー ID)の併記
- 誤操作からの復帰手段の有無
  - 直前操作の取り消し(Undo)の適用範囲
  - 誤削除・誤更新データの復元手順の整備
  - 復帰できない操作の事前明示

  - 学習データの偏りの評価と是正
  - 公平性指標の定義と継続計測

- 静的解析・コードレビューによる欠陥摘出の仕組み

  - コードレビューの必須化とレビュー観点の共有
  - 摘出した欠陥傾向の開発プロセスへのフィードバック
- 稼働環境の経年劣化対策(定期再起動ポリシー等)
  - 長期稼働で劣化する資源(メモリ、ハンドル)の監視

  - ハードウェア・インフラの経年劣化の把握(該当する場合)

- AI モデルの劣化(ドリフト)の監視

  - 失敗データの再処理手段の事前整備
  - 再処理の対象範囲指定(期間・キー指定)の柔軟性
  - 再処理時の重複防止(冪等性)
- 部分復旧(特定テナント・特定データのみ)の可否
  - テナント単位・データ単位の復元可否
  - 全体復元によって他テナントへ影響を与えないこと
  - 部分復旧の所要時間と手順の整備
- 復旧の優先順位定義(業務影響度ベース)
  - システム・機能の復旧優先順位の事前定義
  - どの業務から戻すかの業務部門との合意
  - 優先順位に沿った復旧手順書の構成
- 障害発生時のユーザー・関係者への告知(ステータスページ)
  - ステータスページ・告知手段の整備
  - 告知の基準(どの規模で出すか)と文面テンプレート
  - 復旧見込み・進捗の継続更新
- 障害対応手順書(ランブック)の整備と実効性
  - 主要障害パターンのランブック整備
  - 構成変更に追従した手順の最新性の維持
  - 初動対応者がランブックだけで動けるかの検証
- ポストモーテム(振り返り)と再発防止の定着
  - 障害後の振り返りの実施ルール(個人を非難しない文化)
  - 再発防止アクションの追跡と完了確認
  - 学びの共有(他チーム・類似システムへの水平展開)
- 障害対応・DR 訓練の実施しやすさ
  - 定期的な DR 訓練・障害対応訓練の計画
  - 訓練を安全に実施できる環境の整備
  - 訓練結果に基づく手順・体制の改善

### セキュリティ(Security)

#### 機密性(Confidentiality)

  - ロール設計と最小権限での付与
  - 定期的な権限棚卸しと過剰権限の回収
  - 機能・データ・API 各層でのアクセス制御の実装
  - デフォルト拒否(許可リスト方式)の徹底
- URL・ID 推測による不正アクセス(IDOR)対策
  - 全リソースアクセス時の認可チェック(所有者・権限の確認)
  - 推測困難な ID の採用(ただし ID 秘匿だけに頼らない)
  - 他人のリソースへのアクセスを試みる認可テストの実施
- 保存データの暗号化
  - 保存時暗号化(ディスク・DB・バックアップ)の適用
  - 機微項目の項目レベル暗号化の要否判断
  - 暗号鍵と暗号化データの分離管理
- 通信の暗号化(TLS 等)
  - 全通信の TLS 化(内部通信を含めるかの方針決定)
  - TLS バージョン・暗号スイートの適切な設定
  - 証明書検証の省略(検証スキップ実装)の排除
- 鍵・シークレットの管理(ハードコード禁止、ローテーション)
  - シークレット管理サービスの利用(コードへの直書き禁止)
  - 定期的・漏えい時のローテーション手順の整備
  - リポジトリへのシークレット混入スキャン
- 個人情報・機微情報の保護(マスキング、仮名化)
  - 個人情報の保有項目・保管場所の台帳化
  - 表示・ログ・帳票でのマスキングの適用
  - 仮名化・匿名化の適用範囲の設計
- 匿名化・統計データの再識別リスク評価
  - 少数件データによる個人特定リスクの評価
  - k-匿名性等の指標による評価
  - 公開・外部提供前のレビュープロセス
- 画面・帳票上の機微情報の表示制御
  - 権限に応じた項目レベルの表示制御
  - デフォルトはマスク表示とし必要時のみ開示する設計
  - 帳票・エクスポートへの機微項目の出力制御
- 画面共有・のぞき見への配慮(マスク表示の切替)
  - パスワード等のマスク表示と一時的な表示切替
  - 画面共有時に映り込む情報の最小化
  - 離席時の自動ロック・セッションタイムアウト
- 検索エンジン・外部への意図せぬ公開防止(noindex、公開設定ミス検知)
  - 認証必須ページのクローラー除外設定
  - ストレージ・リポジトリの公開設定の定期点検
  - 公開範囲設定 UI の分かりやすさ(ユーザーの設定ミス防止)
- ファイルメタデータ(EXIF、作成者情報)経由の漏えい対策
  - アップロード画像の位置情報(EXIF)の除去
  - 文書ファイルの作成者情報・変更履歴の除去
  - システムが生成するファイルのメタデータの点検
- 開発・検証環境への本番データ持ち込み制御
  - 本番データ持ち出しのルールと承認フロー
  - マスキング済みテストデータの生成手段の整備
  - 検証環境のアクセス制御(本番同等の保護)
- 内部不正対策(職務分掌、相互牽制)
  - 開発者・運用者の本番データアクセスの制限と記録
  - 職務分掌(申請者と承認者の分離)
  - 大量ダウンロード等の異常操作の検知
- 不要データの削除(データ最小化・保持期間)
  - 取得項目の必要最小限化
  - 保持期間を過ぎたデータの削除の実施
  - 退会・契約終了時のデータ削除ポリシー
- 廃棄・返却時のデータ消去(メディアサニタイズ)
  - 記憶媒体の確実な消去(規格に準拠した方式)
  - クラウド解約時のデータ削除の確認
  - 消去の記録・証明書の保管
- 間接的な漏えい対策(ログ、エラーメッセージ、キャッシュ、バックアップ経由)
  - ログへの個人情報・シークレットの出力禁止
  - エラー画面での内部情報(スタックトレース)の非表示
  - キャッシュ・バックアップ経由の漏えい経路の点検
- クラウド・SaaS の設定不備の検知(ポスチャ管理)
  - 設定基準(ベンチマーク)との自動照合(CSPM 等)
  - 公開設定・権限設定の変更の検知
  - 重要設定の変更に対する承認プロセス
- 暗号アルゴリズムの陳腐化への備え(暗号アジリティ・耐量子暗号)
  - 使用中の暗号方式・鍵長・証明書の棚卸し(暗号インベントリ)
  - 暗号方式を差し替えられる設計(暗号アジリティ)
  - 耐量子計算機暗号(PQC)への移行計画(NIST は 2030 年非推奨化・2035 年使用禁止の方針)
  - 「今収集して後で解読」(harvest now, decrypt later)リスクの評価
- プライバシー保護の法令対応(開示等請求・同意管理)
  - 本人からの開示・訂正・削除請求(DSAR)への対応手段
  - 利用目的の管理と目的外利用の防止
  - Cookie・トラッキングの同意管理
  - 越境移転・第三者提供の法的根拠の管理

#### インテグリティ(Integrity)

- データ改ざんの検知・防止(署名、ハッシュ)
  - 重要データの改ざん検知(ハッシュ・署名)の実装
  - 改ざん検知時の対応フローの定義
  - 転送中データの完全性検証(チェックサム)
- 入力値検証(SQL インジェクション、XSS、CSRF 等への耐性)
  - プレースホルダー・ORM による SQL インジェクション対策
  - 出力エスケープによる XSS 対策
  - CSRF トークンの実装と検証
- SSRF・XXE・オープンリダイレクト等サーバー側攻撃への対策
  - ユーザー指定 URL へのサーバーからのアクセス制限(SSRF 対策)
  - XML 外部実体参照の無効化(XXE 対策)
  - リダイレクト先の許可リストによる検証
- セキュリティヘッダー(CSP、X-Frame-Options 等)の適切な設定
  - CSP の導入と段階的な厳格化
  - クリックジャッキング対策(frame-ancestors 等)
  - ヘッダー設定の自動チェックの仕組み
- CORS 設定の適切さ
  - 許可オリジンの限定(ワイルドカードの回避)
  - 認証情報付きリクエストの許可設定の妥当性
  - 内部 API への外部オリジンからのアクセス可否の点検
- パラメータ・リクエスト改ざん対策
  - 価格・権限などをクライアント入力から信頼しない設計
  - hidden 項目・Cookie の改ざんを前提としたサーバー側検証
  - サーバー側での金額・権限の再計算・再検証
- 競合状態(TOCTOU)を突いた攻撃への耐性
  - 確認と消費の間の競合の排除(原子的な操作)
  - クーポン・ポイントの同時使用による多重取得の防止
  - レースコンディションを想定した並行アクセステスト
- ファイルアップロードの検証(拡張子偽装、マルウェア)
  - ファイル内容の実体検証(拡張子・Content-Type だけに頼らない)
  - マルウェアスキャンの実施
  - アップロード先での実行防止・別ドメインからの配信
- デシリアライゼーション等の攻撃への耐性
  - 信頼できないデータのデシリアライズの回避
  - 安全なフォーマット・許可型リストの使用
  - 関連ライブラリの既知脆弱性の確認
- 依存ライブラリ・サプライチェーンの完全性(SBOM、署名検証)
  - SBOM の生成と管理
  - パッケージの署名・チェックサムの検証
  - ビルドパイプライン自体の改ざん防止
- 設定・構成情報の改ざん防止(権限分離、IaC)
  - 本番設定変更の権限制限と変更記録
  - IaC 化による構成変更のレビューと履歴管理
  - 手動変更による乖離(ドリフト)の検知
- 承認ワークフローによる業務データの保全
  - 重要データ変更への承認フローの適用
  - 承認の形骸化防止(変更内容が確認できる承認画面)
  - 承認済みデータの事後変更の制限
- 時刻同期(NTP)によるタイムスタンプの信頼性
  - 全サーバーの時刻同期の設定と監視
  - 時刻ずれの検知とアラート
  - 法的証明が必要な場合の信頼できる時刻源の利用
- データ整合性チェック(チェックサム、突合)
  - 移送・変換前後の件数・金額の突合
  - 定期的な整合性検証ジョブの実施
  - 不整合検知時の原因追跡手段の確保

#### 否認防止性(Non-repudiation)

- 電子署名の利用
  - 署名が必要な文書・取引の特定
  - 署名方式の選定(電子署名法との整合)
  - 署名を長期的に検証できる手段の維持
- タイムスタンプによる時刻証明
  - 時刻認証局(TSA)によるタイムスタンプの利用
  - タイムスタンプの有効期限と更新(長期署名)
  - 適用対象(契約書、証跡ログ等)の定義
- 重要操作(承認、決済、削除)の証跡確保
  - 重要操作の定義と証跡取得の網羅
  - 操作前後の状態を含む記録
  - 証跡が欠落しないこと(取得失敗時の扱い)の担保
- 配信・受領の証明(送達確認)
  - 送達・開封の記録の取得
  - 受領確認(受領操作、受領書)の仕組み
  - 送達記録の保全と提示可能性
- 同意取得(利用規約、個人情報)の記録
  - 同意した規約のバージョン・日時・方法の記録
  - 規約改定時の再同意の取得
  - 同意の撤回とその記録
- 証跡の改ざん不可能な保全(WORM、外部保管)
  - 追記のみ(WORM)ストレージ等での保全
  - 管理者であっても証跡を消せない権限設計
  - ハッシュチェーン等による改ざん検知
- 証跡の法的有効性(規格・ガイドライン準拠)
  - 業界の証跡要件・ガイドラインの把握
  - 証拠として通用する形式・運用であることの確認
  - 法務・監査部門との要件のすり合わせ
- 法的要件(電子帳簿保存法等)への適合
  - 適用される法令(電帳法、e-文書法等)の特定
  - 検索要件・訂正削除履歴等の要件充足
  - 制度改正への追従体制

#### 責任追跡性(Accountability)

- 監査ログの取得範囲(誰が・いつ・何を・どこから)

  - 主体・日時・対象・操作・接続元の記録
  - 参照系操作(閲覧)まで記録するかの判断
- 共有アカウントの排除(操作者の個人特定可能性)
  - 個人アカウント原則と共有アカウントの棚卸し
  - やむを得ない共有アカウントの貸出管理
  - すべての操作が個人に紐付くことの確認
- API・システムアカウントの行為の追跡(人間以外の主体)
  - サービスアカウント・API キー単位の識別
  - 自動処理の実行主体・トリガーの記録
  - システムアカウントの権限最小化と棚卸し
- 特権操作・管理者操作の記録と監視
  - 特権 ID の利用申請・承認の記録
  - 特権セッションの操作記録(コマンドログ等)
  - 特権操作のリアルタイム監視・アラート
- 外部委託先・外部サービスへのデータ提供の記録
  - 提供先・提供データ・目的の記録
  - 委託先でのアクセス記録の取得・報告の取り決め
  - 提供終了時のデータ削除の確認
- トレース ID 等によるログの相関・追跡可能性
  - リクエスト単位のトレース ID の付与と伝播
  - システムを跨いだ処理の追跡可否
  - ユーザー・取引単位での横断検索
- ログの改ざん検知
  - ログの完全性検証(ハッシュ、署名)
  - ログの削除・変更の権限制限
  - ログ基盤への即時転送(ローカルでの改ざん余地の低減)
- ログの一元集約と横断検索(SIEM)
  - 各システムのログの集約基盤への転送
  - 時刻同期による突き合わせ可能性の確保
  - 相関分析による異常検知
- ログの保全性・保存期間・検索性(監査対応)
  - 法令・監査要件に基づく保存期間の設定
  - 長期保存ログの検索性の確保
  - 監査要求時の抽出・提出プロセスの整備
- アカウント棚卸し(退職・異動時の権限回収)
  - 入退社・異動と連動したアカウント処理
  - 定期的な全アカウント・全権限の棚卸し
  - 休眠アカウントの検出と無効化
- 内部統制・IT 全般統制(ITGC)への対応
  - アクセス管理・変更管理・運用管理の統制の整備
  - 統制の証跡(承認記録、レビュー記録)の保全
  - 内部監査・外部監査への対応プロセス

#### 真正性(Authenticity)

- 認証方式の強度(多要素認証、パスワードポリシー)
  - MFA の提供と重要操作・管理者への必須化
  - パスワードポリシー(十分な長さ、漏えいリスト照合)の設定
  - 認証試行の記録と異常の検知
  - 認証処理の共通基盤・実績あるライブラリの利用(独自実装の回避)
- フィッシング耐性の高い認証(パスキー/FIDO2)
  - パスキー・FIDO2 への対応
  - SMS OTP 等フィッシング耐性の低い方式からの移行計画
  - 利用者への安全な認証手段の推奨・誘導
- パスワードリセット・アカウント回復フローの安全性
  - リセットリンクの有効期限・一回性
  - 回復フローが認証強度の抜け穴にならないことの点検
  - リセット実行時の本人への通知(気づける仕組み)
- 登録時の本人確認レベルの適切さ
  - サービスリスクに応じた本人確認(eKYC 等)レベルの設定
  - なりすまし登録の検知(重複登録、使い捨てメール)
  - 法令上の本人確認義務(犯収法等)への対応
- セッション管理(固定化対策、有効期限、無効化)
  - ログイン時のセッション ID 再発行(固定化対策)
  - 有効期限・アイドルタイムアウトの設定
  - ログアウト・パスワード変更時の全セッション無効化
- リスクベース認証・デバイス認証
  - 通常と異なる環境(IP、端末、時間帯)からのアクセスへの追加認証
  - 新しい端末からのログインの本人通知
  - 信頼済みデバイスの管理と解除手段
- 水平・垂直方向の権限昇格の防止
  - 一般ユーザー間(水平方向)のなりすましの防止
  - 一般→管理者(垂直方向)への昇格経路の点検
  - 権限チェック実装の共通化(場当たり実装の排除)
- なりすまし防止(証明書検証、送信元検証)
  - サーバー証明書・クライアント証明書の検証
  - メールの送信ドメイン認証(SPF/DKIM/DMARC)
  - Webhook 等の受信時の送信元検証(署名検証)
- ボット・自動化アクセスの検知
  - ボット検知(CAPTCHA、行動分析)の導入
  - 正当な自動化(API 利用)との区別
  - クレデンシャルスタッフィング攻撃の検知
- データ・ソフトウェアの出所の検証(コード署名)
  - 配布物へのコード署名と検証
  - アップデートの正当性検証(改ざんされた更新の拒否)
  - 取り込むデータ・モデルの出所の確認

#### 耐攻撃性(Resistance)

- 攻撃負荷への耐性(ブルートフォース、DoS/DDoS)
  - DDoS 対策サービス・CDN の利用
  - 処理コストの高い機能(重い検索等)の保護

  - 報告の分析と傾向把握
  - 重大事故の前兆としての活用
- リスクの評価・記録・追跡(リスク台帳)
  - リスク台帳の維持と定期レビュー
  - 対策の実施状況の追跡
  - 残留リスクの明示
- 変更時のリスク再評価プロセスの定着
  - 変更管理へのリスク評価の組み込み
  - 小さな変更の積み重ねによるリスク変化の把握
  - 再評価結果の記録
- 規制当局・監督官庁への報告義務とフローの整備
  - 報告対象となる事象と期限の把握
  - 報告フロー・責任者の明確化
  - 報告実績の記録
- 残留リスクの明示と受容判断
  - 対策後に残るリスクの文書化
  - 受容の判断者と根拠の記録
  - 利用者への開示(注意事項)
- AI 規制・ガバナンス要件への対応(EU AI Act 等)
  - 自社 AI のリスク分類(高リスク該当性)の判定
  - 高リスク AI の要求事項(リスク管理、データガバナンス、ログ保持、人による監視)への対応
  - 適用スケジュール・法改正動向の追跡(域外適用の確認)

#### フェイルセーフ(Fail Safe)

- 安全状態の定義の明確さ
  - システムごとの「安全な状態」の定義
  - 停止が安全とは限らないケースの考慮
  - 安全状態への移行手順の設計
- 故障時に安全側の状態へ移行する設計
  - 故障モードごとの移行先の設計
  - 移行の自動性(人手に頼らないこと)
  - 移行動作の試験による確認
- 緊急停止手段の提供と即応性
  - 緊急停止の操作手段と分かりやすさ
  - 停止の即応性(遅延なく効くこと)
  - 停止後の再開手順の安全性
- 人による最終確認(ヒューマンインザループ)の組み込み
  - 重大な影響のある処理への人の確認の介在
  - 確認の形骸化防止(内容が見える確認)
  - 自動化する範囲と人が確認する範囲の境界定義
- 自動制御・自動処理の暴走に対する上限・制動(リミッター)
  - 自動処理の処理量・金額等の上限設定
  - 上限到達時の停止と通知
  - 暴走の検知(異常な実行頻度・処理量)
- 安全機能の冗長化・多重化
  - 安全機能の多重化(単一故障で失われないこと)
  - 多様性(異なる方式による冗長化)の検討
  - 冗長系の定期的な動作確認
- ウォッチドッグ・デッドマン機構による監視
  - ハング・停止の検知(ウォッチドッグ)
  - 検知時の自動処置(再起動、安全側への移行)
  - 監視機構自体の信頼性
- 縮退運転時にも安全機能が維持されること
  - 縮退時に安全機能を落とさない設計
  - 縮退状態での安全性の検証
  - 縮退が連鎖した場合の最低保証ライン
- 電源断・通信断など想定外事象での安全確保
  - 電源断時のデータ・状態の保護
  - 通信断時の安全側動作(勝手に動き続けないこと)
  - 復電・復旧時の安全な再開

#### 危険警告性(Hazard Warning)

- 危険状態の検知と即時の警告
  - 危険状態の検知手段と検知までの時間
  - 警告の即時性(遅延の管理)
  - 検知できない危険の把握(検知範囲の明確化)
- 警告の視認性・可聴性(アラーム設計)
  - 気づける表示・音・振動の設計
  - 作業環境(騒音下等)での気づきやすさ
  - 見落とし時の再警告・エスカレーション
- 非常時でも理解できる警告表現(多言語・図記号)
  - パニック時でも分かる簡潔な表現
  - 図記号・色による直感的な伝達
  - 多言語・やさしい表現の併用
- 重大度に応じた警告の優先度付け・区別
  - 重大度レベルの定義と表示の区別
  - 重大警告が軽微な通知に埋もれないこと
  - 同時多発時の優先表示
- 誤報率と失報率のバランス設計
  - 誤報(過剰警告)と失報(見逃し)のトレードオフの調整
  - 検知閾値の根拠と定期見直し
  - 誤報・失報の実績の計測
- 警告過多(アラート疲れ)の防止
  - 警告件数の監視と削減
  - 重複警告の集約
  - 対応不要な警告の排除
- 警告の抑止・無効化操作の管理(安易なミュートの防止)
  - ミュート・抑止の権限と期限の管理
  - 抑止中であることの可視化
  - 抑止の記録と定期レビュー
- 警告時に取るべき対処の明示
  - 警告と対処手順の紐付け
  - その場で分かる対処ガイダンス
  - 対処後の警告解除の確認
- 警告発生履歴の記録と分析
  - 警告履歴の保存と検索性
  - 頻発する警告の傾向分析と根本対策
  - 事故調査への活用可能性

#### 統合時安全性(Safe Integration)

- 他システム・機器と統合した際の安全性維持
  - 単体で安全でも組み合わせで危険にならないかの確認
  - 統合相手の故障・異常動作の影響評価
  - 統合構成全体での安全責任の明確化
- 安全関連データ授受の確実性(欠落・遅延の防止)
  - 安全に関わるデータの欠落・遅延の検知
  - データの鮮度・有効期限の管理
  - 授受失敗時の安全側動作
- 統合先への安全要件の伝達と検証
  - 安全要件の仕様書としての伝達
  - 統合先が要件を満たしていることの確認方法
  - 要件変更時の再伝達
- 組み合わせ状態での安全検証(統合試験)
  - 統合状態での安全機能の試験
  - 異常系(片系故障)の組み合わせ試験
  - 実運用に近い条件での検証
- 機能安全規格(IEC 61508、ISO 26262 等)との整合
  - 適用規格の特定と要求水準(SIL/ASIL 等)の決定
  - 規格が求めるプロセス・文書の整備
  - 認証・適合性確認の計画
- 人と機械が協調する場面での安全(HMI 設計)
  - 人と機械の役割分担の明確さ
  - 機械の状態・意図の人への伝達
  - 人の誤解・誤操作を誘わない HMI 設計
- 保守・点検作業時の安全確保(作業時モード)
  - 保守モードでの動作制限
  - 作業中の誤起動の防止(ロックアウト・タグアウト)
  - 作業完了後の復帰確認
- 緊急時の関係者間連絡・連携体制
  - 緊急連絡網・連絡手段の整備
  - 関係組織(統合相手)との連携手順
  - 連絡体制の訓練による実効性確認
- 統合構成変更時の安全性再評価
  - 構成変更(バージョンアップ、機器交換)時の再評価プロセス
  - 相手側の変更の通知を受ける取り決め
  - 再評価結果の記録
